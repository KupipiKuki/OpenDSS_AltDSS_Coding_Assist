## Traps, in the order they will bite

1. **Line endings will destroy your checksums.** The repo has `core.autocrlf = true` and no `.gitattributes`. Upstream fixture files are CRLF: `IEEE13Nodeckt.dss` hashes to `033ccd40…` as CRLF but `cee69d36…` with LF endings. Committing it normally stores LF in the blob, so the recorded SHA-256 matches neither the blob nor a Linux checkout. Add `examples/fixtures/.gitattributes` with `* -text`, then prove byte identity with `git cat-file -p <rev>:<path> | sha256sum` for every fixture file and record that proof in the build audit.
2. **The `IEEELineCodes.DSS` in each bus folder is a 30-byte stub** containing exactly `redirect ../IEEELineCodes.DSS`. Copying only `13Bus/` or `34Bus/` produces a fixture that cannot compile. Do not inline the shared file, do not rewrite the redirect, do not "tidy" the path — the closure is the fixture.
3. **Keep the upstream case of every filename.** `IEEELineCodes.DSS` and `IEEELineCodes.DSS` differ from `IEEELineCodes.dss` on a case-sensitive filesystem, and the redirect names the file exactly.
4. **`ieee34Mod1.dss` never solves.** It ends at `CalcVoltageBases` (L246). The harness must set its own solver options and issue `Solve` after compiling. Do not add a `Solve` line to the fixture file.
5. **`IEEE13Nodeckt.dss` does solve, and then does more.** It ends with `calcv`, `Solve` (L148-L149) and then `BusCoords IEEE13Node_BusXY.csv` (L150). The embedded solve runs during `Redirect`; the harness must then set its options and re-solve so both fixtures are handled identically.
6. **Never run the upstream `Run_*.dss` files.** They contain `plot circuit` and `Plot profile`, and the 34-node one compiles twice with forced regulator taps. Headless runs must drive `ieee34Mod1.dss` directly.
7. **Fresh context per fixture.** Reuse of a context leaks element state; construct a new context (or `Clear` plus a new circuit) for each fixture and for each repeat run.
8. **The 34-node case needs more control iterations than the default maximum implies.** Measured: 6 control iterations and 25 total iterations against a default `MaxIterations` of 15. Do not raise the limits to "make it converge"; record the options as they are and let the golden carry them.
9. **The single `LoadShape` named `default` is the engine's built-in shape**, not a fixture-authored one. Do not claim LoadShape coverage from these fixtures in the audit, the workflow, or the manifest.
10. **The golden file is generated, never typed.** If you find yourself editing a number in `golden.json`, stop: either the harness is wrong or the fixture is. `--update-golden` is for a new revision, not for making a failing comparison pass.
11. **Do not hand-edit fixture files.** If a circuit genuinely needs a change, the rule is an overlay file plus a written rationale in the fixture record — but nothing in this package should need one.
12. **Prove determinism.** Run the harness twice in the same environment and diff the two goldens: they must be byte-identical apart from nothing at all. Then run from a different working directory to confirm the relative redirects resolve from the script location, not from the CWD.

## Requirements and acceptance

1. `tools/run_fixtures.py` exits 0 on a clean checkout of the committed fixtures and non-zero when a single golden quantity is perturbed (demonstrate the failure path in the build audit).
2. `--update-golden` refuses without `--reason`, refuses when fixture files have uncommitted changes, increments `golden_revision`, and writes `update_reason`.
3. Every fixture file's SHA-256 matches `fixtures.json`, and the blob check from trap 1 passes at the committed revision.
4. `tools/validate_catalogs.py` passes with the new fixtures schema pair, on the extended total.
5. `PROVENANCE.md` for each fixture records repository, commit, retrieval date, licence with both copyright holders, the file table with checksums, and the deliberately-not-copied table.
6. `references/sources.json` gains the fixture repository record, and both fixture records resolve their `source_ids`.
7. The build audit records the environment block, the checksum proof, the determinism run, the failure-path demonstration, and the exact commands used.
8. No file outside `docs/`, `opendss_altdss_library/examples/fixtures/`, `opendss_altdss_library/references/`, `opendss_altdss_library/schemas/`, and `opendss_altdss_library/tools/` changes, and no Phase 3 catalog is modified.
